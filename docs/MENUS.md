# Menus

Fictional businesses, `menu@0.6` JSON in `data/menus/`. Run `make menus` to validate them and print each
menu's content hash (`menu_version`), which every quote and run records.

| Business | File | Cuisine / tests | Hours (local) | Delivery | Name for pickup |
|---|---|---|---|---|---|
| Corner Patty | `corner-patty.json` | burgers: ingredients to remove, add-ons, a default size, a flavor with no default, a combo with two slots | 11:00–22:00 New York | $3.99, min $15 | optional |
| Halfmoon Pizza | `halfmoon-pizza.json` | pizzas: 8 pizzas × 5 sizes (no default), 23 toppings, 3 sauces, 4 crusts (exclusive), half-and-half, 2 sides, 6 drinks (sodas: can / 20 oz / 2-liter) | 12:00–23:00 Chicago | $2.99, min $12 | optional |
| Morning Crumb Café | `morning-crumb.json` | café/bakery: drink sizes without defaults, milk substitution (exclusive), extra shots, pastry flavors, a combo whose choices need a size | 07:00–15:00 Los Angeles | **none** (pickup only) | **required** |
| Lucky Lime Taqueria | `held_out/lucky-lime.json` | **held-out, tests only**: proteins as required variants, tortilla choice (exclusive), a combo with two taco slots that each need a protein | 10:30–21:30 Denver | $3.49, min $20 | optional |

Corner Patty and Halfmoon Pizza started as the M0 sample menus (decision 2026-10-07). Morning Crumb and
Lucky Lime are new. The opening hours are chosen so that a bare "at 7" means 7 pm at Corner Patty but
7 am at Morning Crumb, and so the rules baseline's "only one reading is open" normalization is exercised.

## Held-out menu

Lucky Lime is used **only** for writing and evaluating test conversations, to measure generalization to an
unseen business (spec §7). `load_menus()` leaves it out unless called with `include_held_out=True`, and
its item ids share nothing with the other menus (tested). Synthetic generation, prompt tuning, few-shot
examples and training must never load it; M2/M4 add checks for those code paths.

## Halfmoon vs. the PIZZA benchmark catalog

Halfmoon is a realistic neighborhood pizzeria and is the menu for chat data (dev/test, synthetic) and the
demo. It is **not** used to evaluate on the PIZZA dataset (amazon-science/pizza-semantic-parsing-dataset,
CC-BY-NC-4.0, confirmed from its LICENSE and README).

PIZZA evaluation uses a separate **PIZZA benchmark catalog**, generated by the M2 script into the gitignored
`data/external/` and never committed (nor is any other PIZZA-derived file, such as an entity map):

1. Randomly sample ~200 orders from the dataset's test split with a fixed seed. Orders are never filtered to
   fit a menu.
2. Build the catalog from only the toppings, sizes, styles and drinks those orders mention, then add unused
   distractor items to reach a realistic menu size (~30–40 toppings).
3. Report how many entities of each type the sample uses, and convert the orders against that catalog.

The benchmark catalog is used only for the PIZZA evaluation, never for chat data, prompts or the demo.
